## Description

From http://open-std.org/jtc1/sc22/wg21/docs/papers/2013/n3797.pdf
If the value returned by the operator-> function has class type, this may result in selecting and calling another operator->
function. The process repeats until an operator-> function returns a value of non-class type.

OK - this doesn't work.
The issue is - in 
Synchronized<Optional<float>> x;
if SYNCHROnNIZEd operator-> returns ptr, then x->IsMissing (), x->Value() etc work. 
But if it returns  a ptr, then
struct fred { int a; }
Synchonized<Optional<fred>> x;
x->a WONT work.
Making synchonized operator-> return struct (when T has operator->) solve the later problem, but breaks the former.
