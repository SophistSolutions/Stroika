## Description

Clearly document design choice on “SortedXXX” versus “Sorted” mixin versus Sterls suggestion of “Sorted” attribute in traits. Gist of reason is that using traits is hard, and obscure, and using sorted class is COMMON requirement (even if beneath the covers it was implemented using traits).
[ I LIKE idea of traits but advantage of current scheme is ]
class SortedSet<T> : public Set<T> - so follows same API/inherites. Not so if you use TRAITS. Tahts biggest reason.
