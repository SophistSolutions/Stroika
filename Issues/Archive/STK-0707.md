## Description

See https://stackoverflow.com/questions/14215784/why-cancellationtoken-is-separate-from-cancellationtokensource
and 
https://docs.microsoft.com/en-us/dotnet/api/system.threading.cancellationtokensource?view=netframework-4.8
and 
https://docs.microsoft.com/en-us/dotnet/api/system.threading.cancellationtoken?view=netframework-4.8
My current mechanism appears on the surface much simpler to use (no need to explicitly pass around the cancelation tokens).
But the CancelationToken mechanism works better in supporting tasks that cross multiple threads (e.g.. using athread pool and little mini tasks).
And my current mechanism has defects with condition variables and blocking (I need to busy wait a little). Not sure if CancelationTokens would solve this or not.
