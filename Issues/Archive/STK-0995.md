## Description

Utitity algorithm/class. Helpful to keep staticis in places like LRUCache and / or ThreadPool (longevity).

Optimisitcally store a core number of elelements. (array).
To compute a median, you need ALL the elements and a partial sort.
But if you want to NOT keep all the elements, there is no way to compute the median.
But you can take a GUESS ath th emedian.
And keep track o fthe number of entries above or below it.
And each new element that comes in  - you adjust number of elts above or below that ‘almost median’.
Then report ‘best cheap median estimate is XX, but N1 elts above it and N2 elts below it’.
If numbers that come in are truely random (like time taken by a task in a threadpool). maybe this works well and for little cost.
For sorted input data, obviously works poorly, but at least you can tell that the stats were not repsentative cuz you know how many elts above and below that almost-median.
