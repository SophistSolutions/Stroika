### Lewis Pringle - 2023-01-15T12:43:49.250-0500

Thought more about this. As a data structure problem, this probably does NOT make sense. NEEDED to keep map KEY->count info, to support adds. That CANNOT map backwards (without lots of extra gorp). Easist way would be to keep two data structures - mapping in both directions (like bijection). But that would be a lot of cost. Worth while if no better way, but there is a better way for most use cases.
New API 
Iterable<T>::Top()
Takes function param (sort order). And optional max count. Then very efficeintly (OR N * LOG(fix num returned count) ) - so effectively for Top(3) - O(N).
This can then be shaddowned in the Mutliset class.

So if you want items -in count order just say:
Multiset<int> x;
x.Top (3) - and you get a list of the top three items.
For case where you BUILD list and then call Top () once, this is STRICTLY more efficient than any other data structure I know of to produce this answer. ONYL benefit of keeping data in Multiset object is if calling repeatedly to get Top (N).
