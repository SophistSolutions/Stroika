## Description

e.g. want:
static constexpr TimeOfDay kMin {0};
Doing that inside struct TimeOfDay fails cuz TimeOfDay is incomplete at that point so cannot be declared literaltype.
From what I saw in various docs - that seems wrong - but clang/gcc/msvc all agreee.
I should also be able to do const inside the static declaration, and then use constpr as definition. This works so long as I only put the constexpr guy in one file. BUt attempting to add to a second gets duplicate defs error (warning on windows, error on unix).
https://wandbox.org/
seems to work…
struct A {
int f;
constexpr A () : f (0) {}
constexpr A (int i) : f  {}
//static constexpr A kMin {3};	// doesn’t work cuz compiler says A incomplete type
static const A kMin;
};	
constexpr A A:: kMin {3};	// but then generates link errors  - dup defined
I realized template std::numeric_limits has this same issue - I'm trying todo. But it uses functions:
T numeric_limits<T>::max ().
So I used that pattern.
Note here that if I can find a way around this, then it would be better to go back to kMax/kMin instead of min()/max() functions. But this is functional, and OK for now. easy on any compiler etc.

### Lewis Pringle - 2018-11-05T13:29:04.544-0500

http://open-std.org/jtc1/sc22/wg21/docs/papers/2013/n3797.pdf
A static data member of literal type can be declared in the
class definition with the constexpr specifier; if so, its declaration shall specify a brace-or-equal-initializer
in which every initializer-clause that is an assignment-expression is a constant expression. [ Note: In both
these cases, the member may appear in constant expressions. — end note ] The member shall still be defined
in a namespace scope if it is odr-used (3.2) in the program and the namespace scope definition shall not
contain an initializer.

### Lewis Pringle - 2020-08-20T11:51:12.598-0400

This is now fixed.
The trick is:
struct X { 
static const X kValue;
};
inline constexpr X::kValue{initializer};
